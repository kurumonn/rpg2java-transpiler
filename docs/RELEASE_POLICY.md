# リリース方針（SemVer）

## 目的

商用運用時のアップグレード判断をしやすくするため、
本プロジェクトのバージョニングとリリース運用ルールを定義します。

## バージョニング

- `MAJOR.MINOR.PATCH` の **Semantic Versioning** を採用します。
- 各更新の扱い:
  - **MAJOR**: 互換性を壊す変更（CLI引数の削除/意味変更、出力仕様の破壊的変更）
  - **MINOR**: 後方互換を保った機能追加（命令対応追加、オプション追加）
  - **PATCH**: 後方互換を保った不具合修正/ドキュメント修正

## リリース判定

リリース作業前に以下を満たすこと:

1. CI必須チェックがすべて成功
2. `CHANGELOG.md` の `Unreleased` が更新済み
3. 既知の重大不具合が未解決でない
4. ローカルで `./scripts/release_precheck.sh` を実行し、結果を確認

## リリース手順（最小）

1. `CHANGELOG.md` の `Unreleased` をリリース版に確定
2. バージョンタグ作成（例: `v0.2.0`）
3. GitHub Releases にノートを作成
4. 必要に応じてバイナリとチェックサムを添付

## 運用メモ

- 命令変換ロジックの変更は、可能な限りE2E fixtureを追加してからリリースする。
- `--mode auto/free/fixed` の挙動差に影響する変更は、READMEに追記する。
