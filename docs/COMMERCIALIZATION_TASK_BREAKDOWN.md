# 商用レベル化に向けたタスク分解（README次アップデート案）

## 目的

現状の「安全な移行の土台」から、**導入判断・運用・監査に耐える商用品質**へ引き上げる。

## マイルストーン

- **M1: 変換品質の可視化強化**（2週間）
- **M2: 未実装命令の重点対応**（3週間）
- **M3: CI/CDとリリース運用整備**（2週間）
- **M4: 運用・セキュリティ・サポート体制**（2週間）

---

## Epic 1. 変換精度と互換性の底上げ

### E1-1: 未実装命令の優先実装
- [ ] `EXSR` のIR化とJava変換ルール策定
- [ ] `SETLL` / `READE` / `CHAIN` のアクセス系変換を実装
- [ ] 各命令ごとに成功例/境界値/異常系のfixture追加

### E1-2: 意味検証の強化
- [ ] 変換前後で比較可能な中間サマリ（制御分岐数、I/O回数）をレポート追加
- [ ] TODO発生率を閾値管理（例: 10%超で警告）
- [ ] `--strict` モード（未知命令をエラー扱い）追加

### E1-3: Java出力品質改善
- [ ] 生成コードの命名規約統一（メソッド/変数）
- [ ] スタブAPIのインターフェース設計を固定化
- [ ] Java 21/25両ターゲットの差分検証テストを追加

---

## Epic 2. 品質保証（QA）とテスト戦略

### E2-1: テストピラミッド整備
- [ ] parser/codegenのユニットテストを主要命令網羅まで拡充
- [ ] E2Eを「小規模/実コーパス/退行防止」に分類
- [ ] スナップショット更新手順をCIで強制（差分レビュー必須化）

### E2-2: 品質ゲート定義
- [ ] CI必須ゲート: `fmt`, `clippy -D warnings`, `cargo test --tests`, `javac-check`
- [ ] TODO率・失敗率・処理時間のしきい値管理
- [ ] mainブランチ保護ルール（レビュー人数/必須チェック）を明文化

### E2-3: 非機能テスト
- [ ] 大量ファイル時の性能回帰テスト（N=1000想定）
- [ ] メモリ使用量計測（ピーク追跡）
- [ ] 異常入力（壊れた固定長/巨大行）の耐障害性テスト

---

## Epic 3. 配布・運用・サポート

### E3-1: リリース運用
- [ ] SemVerに基づくリリース方針策定
- [ ] CHANGELOG運用開始
- [ ] バイナリ配布（GitHub Releases）とチェックサム公開

### E3-2: オペレーション
- [ ] 障害対応Runbook作成（変換失敗/性能劣化/誤変換疑い）

- [ ] サポート窓口向けテンプレート（再現情報チェックリスト）を作成

### E3-3: ドキュメント整備
- [ ] READMEに「商用導入チェックリスト」を追加
- [ ] `docs/` に運用設計書（SLO/SLA、バックアップ方針）を追加
- [ ] 実コーパス運用ガイドを匿名化・監査観点で拡張

## 実行順（推奨）

- 主要コーパスで `success=100%` を維持
